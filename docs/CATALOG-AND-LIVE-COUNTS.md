# 数量与更新

## 为什么设置100还只有20

旧版100是“每轮最多采集”，不是已有插件数，也不会发现新插件。种子清单只有20个，因此列表仍只有20条。现在增加了独立的“收录目标”和真实插件发现。

- **全库**：已有有效数据的插件总数；首页统计以它为准。
- **匹配**：当前搜索和筛选后剩余数量。
- **展示**：匹配后按排序取前N项的数量，分页只在这个范围内。
- **收录目标**：希望把目录扩充到多少个；会查找并核验真实DSH插件。
- **每轮最多采集**：本轮取得指标的插件上限，优先更新从未采集或最久未更新的插件。

目标50不意味着瞬间已有50。如果搜索、身份核验、请求预算或有效指标不足，会显示实际数量和原因。减少目标不会删除已收录插件；只想少看一些时使用展示数量。

## 手动更新

1. 网站右上角“数据更新”，选择“重新采集一次”，填写“收录目标”；需要时展开预算。
2. 点“到GitHub更新数据”，登录后点Run workflow，分支选main、action选refresh，按网页表格填 target_plugins、max_plugins、max_requests、github_reserve，确认运行。
3. 等工作流采集和发布完成，返回网站点“刷新已发布数据”。

refresh一次完成保存本次设置、查找核验、采集和发布。configure只保存设置。网站仅支持手动采集；这两个操作都不会开启定时采集。网页不存放访问令牌，采集操作需要仓库写入权限。

## 数字怎样更新

所有业务数字来自有效JSON快照或当前筛选结果。页面可见时每60秒检查一次已发布快照，恢复前台时检查；后台不轮询。新快照就绪后，统计、生态图、列表和更新记录一起变化。

这60秒检查只读取网站文件，不是每分钟重新调用GitHub。采集只在维护者手动执行时发生，显示上次真实采集时间。读取失败保留旧数据。

## 新插件如何核验

按Stars获取有界候选，核对公开独立仓库、package.json中的DSH bundle声明、对应的安装说明；npm安装还核对官方registry的仓库和bundle信息。不安装、不执行插件。核验不等于安全审计，不把关键词命中直接算作插件。

扩充目录保存至data分支catalog.json，下一轮保留已核验身份和旧ID。请求预算涵盖搜索、验证、指标、分页和重试；触及预算保留旧指标快照。搜索额度与普通仓库额度分开处理。

该目录不宣称覆盖全部GitHub，也不承诺一定找到任意数量。规范依据：[DSH插件打包文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/basic/publish.md)。

## 本轮验证

2026-10-23：真实只读查询以现有20个为起点，检查71个候选，新增核验30个，达到50个目录；共211次请求。该验证仅写本地验收证据，不把候选或合成指标注入网站。163项单元测试、47项浏览器测试、类型检查、生产构建和产物扫描通过。
